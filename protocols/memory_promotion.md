# 记忆提升协议

## 目的

只提升经过审查且具有超出当前任务的持久价值的知识。

## 提升关口

- 提升只在发布复盘和人工确认之后发生。
- 不要提升草稿、未经验证的假设、一次性偏好或普通任务笔记。
- 有用观察可以先作为原始活动日志、复盘记录或结构化记忆收集，但它们不是持久提升记忆。
- 提升文件只在复盘期间或之后生成，并且在进入本地长期记忆或框架候选前需要人工确认。

## 推荐目标位置

- `storage/memory/notes/`：已确认、可复用的本地长期记忆。
- `storage/skills/`：可重复使用的本地方法、提示词、工作流或生产 Skill。
- `storage/library/`：私有领域知识、资料库、资产索引、示例和参考材料。
- `storage/memory/candidates/`：待审查的沉淀候选。
- `public framework candidate`：审查后可能进入公开 GitHub 的通用协议、模板、插件或公共 Skill 改进。

旧的 `knowledge/`、`domains/`、`skills_local/` 和 `assets_index/` 只作为兼容迁移来源，不再作为新提升的推荐目标。

## 必要元数据

- `source`：知识来源，包括任务、产物、复盘、指标或人工确认。
- `scope`：知识适用范围，例如框架、项目、领域、平台、格式或受众。
- `trigger`：未来什么任务或场景应该读取它。
- `risk`：隐私、许可、准确性、公开适合度、运营敏感性和潜在过度泛化。

## 审查规则

- 当范围不确定时，优先选择较窄的本地提升，而不是宽泛的框架提升。
- 被拒绝候选只有在仍有审计价值时，才保留在原始记录或复盘记录中。
- 不要将私有本地内容提升到公共框架目标位置。
- 没有触发条件的记忆不能进入长期 `notes/`。
- 没有明确输入、输出和边界的流程不能沉淀为 Skill。
